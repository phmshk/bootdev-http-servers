# Technical Documentation

## Architecture
The server is built using Go's net/http package. It follows a modular structure:
- main.go: Server entry point and route registration.
- handlers: Endpoint logic divided by resource (users, chirps, auth).
- internal/database: Data access layer generated by SQLC.
- internal/auth: Logic for JWT creation and validation.
- middleware: Request tracking and metrics.

## API Reference

### Health
- GET /api/healthz: Returns OK if server is running.

### Authentication
- POST /api/login: Authenticates user and returns access and refresh tokens.
- POST /api/refresh: Generates new access token using a refresh token.
- POST /api/revoke: Revokes a refresh token.

### Users
- POST /api/users: Registers a new user.
- PUT /api/users: Updates credentials for an authenticated user.

### Chirps
- POST /api/chirps: Creates a new chirp.
- GET /api/chirps: Retrieves all chirps (optional sorting by id).
- GET /api/chirps/{chirpID}: Retrieves a single chirp by ID.
- DELETE /api/chirps/{chirpID}: Deletes a chirp (owner only).

### Webhooks
- POST /api/polka/webhooks: Upgrades user to Chirpy Red status.

### Admin
- GET /admin/metrics: Displays request statistics in HTML.
- POST /admin/reset: Clears all users from database (Dev mode only).

## Database
Uses PostgreSQL with SQLC for type safe queries. Migrations are managed via SQL files in sql/schema/.
